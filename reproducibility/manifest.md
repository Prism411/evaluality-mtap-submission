# Reproducibility manifest

This manifest maps each principal manuscript or supplementary result to its
analysis entry point and archived non-media inputs. All paths are relative to
this `reproducibility/` directory and are also present at the root of the
`mtap-revision-reproducibility.zip` private-release asset.

The JSON outputs are the source of truth for numerical results. The LaTeX
tables are intentionally not regenerated by a formatting script: values are
transcribed from the named JSON fields and can be checked mechanically against
them.

## Fixed analysis settings

- Random seed: 42.
- Bootstrap repetitions: 10,000.
- KADID resampling unit: reference image.
- Constructed-pair resampling unit: source segment.
- Matched-input control: ten uniformly spaced 1-fps frames per candidate and
  arithmetic-mean pooling for both SIFT--BoVW and LIQE.
- Application resampling units: topic, and topic then cluster for the
  hierarchical sensitivity analysis.
- Strict pairwise accuracy: ties remain in the denominator and count as neither
  correct nor incorrect.
- Direction alignment: `rho* = s_m s_y rho`; method and target polarities are
  recorded separately and absolute values are never substituted for sign
  alignment.
- Primary DOVER output: raw technical branch. The cached raw branch sum is a
  sensitivity analysis only and is not the official standardised fusion.
- DOVER source commit: `f1ddc96215bc7fbcf8f315c65d47905f339c3419`;
  `DOVER.pth` SHA-256:
  `f4a42c0bbc94c94dd7409e7f40887d44c5c30314d1d09e7edf03cc35813b4838`.

## Known reproducibility boundary

Restricted source media and public-database images are not redistributed. The
original neural-inference environment was not captured as a fully pinned
lockfile; therefore, the archive supports exact reconstruction of the reported
statistics from hashed cached scores and inspection of all inference settings,
but not a claim of bit-identical regeneration of every neural score on a new
software stack.

The prediction content and provenance note are tracked on `main`; the original
commit and parent history remain inspectable through the submission release
bundle. Its complete identifier is
`9377c07ca080ac61c7cff80e0ff6c7507b6ebaba`; release-asset hashes are recorded
in `RELEASE_SHA256SUMS`.
